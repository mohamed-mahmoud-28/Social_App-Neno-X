Project Overview

Neno X is a Vite React social network connected to the Route Posts REST API. Authenticated members can publish posts, view global/following feeds, comment and reply, like, bookmark and share, follow people, inspect profiles, discover suggestions, manage profile settings and review activity notifications.

Open Neno X → Register or sign in → Home → create/read posts → like/comment/share → profile or Discover People → follow → notification activity → settings/logout

Authentication stores the returned token in localStorage and sends it as a bearer header. AuthContext fetches profile data and clears the session on 401. Backend authorization remains necessary; hidden buttons are not a security boundary.

State, Synchronization and Notifications

Local state is reserved for transient UI. AuthContext owns token/current user. TanStack Query owns API data through queryKeys. The server API is the long-lived source of truth.

Successful mutation → targeted QueryClient invalidation/cache update → active matching queries refetch → cards, detail, modal, counter and list render shared fresh data

Like: the pending button prevents duplicate presses. Post cache invalidation includes postLikes(postId), so LikesModal refetches and does not retain its former list. Comment: mutations invalidate comments and dependent post views, updating counts from API data. Follow: current user data, profiles and suggestions refresh. Profile photo: AuthContext and embedded-user views refresh.

Notifications: WebSocket, Socket.IO and SSE are not detected. Neno X uses foreground-only 30-second REST polling. NavBar, sidebar and page share query keys. Mark-one/all uses direct cache updates after API success for immediate unread consistency.

No window.location.reload() or location.reload() exists in src.

UI/UX, Responsive, Errors and Performance

The UI uses white cards, slate text, indigo actions, rounded corners and restrained shadows. Mobile uses a toggleable Navbar and single-column layouts. Desktop navigation and sidebar begin at lg to avoid tablet collisions. Focus-visible and reduced-motion styles are global; many list images are lazy loaded.

Queries use cache stale time and deduplication; modals are conditional; offline UI comes from react-use. Feature error states and Toastify use API messages when available; RouteError provides recovery. Security currently relies on bearer token storage, protected routes and 401 cleanup.

Known Issues and Recommendations

  • API calls are distributed across components: add a shared Axios instance and feature services.
  • Cover photo is preview-only: implement persistence only after a verified backend endpoint exists.
  • CounterContext is unused: remove it or give it a real responsibility.
  • Polling is not true push: adopt WebSocket/SSE only if the backend supplies it.
  • Vite warns that the production bundle exceeds 500 KB: add route-level lazy loading and audit imports.
  • Authenticated API interaction needs browser/test-account integration tests beyond static build checks.

Glossary and Summary

Component: reusable UI. Props: component inputs. State: data changing rendering. Context: shared tree data. Query: cached server read. Mutation: server write. Cache invalidation: mark stale and refetch. REST endpoint: HTTP resource URL/method. Authentication: identity proof. Authorization: permission decision. Polling: periodic API read.

Neno X is a React REST social application centered on posts, interactions, people discovery and activity. Its architecture combines React Router SPA navigation, AuthContext identity and TanStack Query server cache. The next highest-value improvements are centralized services, authenticated integration tests, real-time transport when available and code splitting.
